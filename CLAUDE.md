# x3ro-deck

Qt 6 desktop app (C++20, Widgets + QML panels) for running coding agents and Docker Compose stacks across several checkouts, on Linux, macOS and Windows. It drives Claude Code and Codex, and local models behind an Anthropic- or OpenAI-compatible server through either CLI. It needs nothing beyond Qt and libvterm; everything platform-specific sits behind a small interface with one file per OS (`SessionBackend`, `ProcessInfo`, `Notifier`, `GlobalHotkey`, the terminal settings sources, `PtyChannel`).

# Commands

- Configure with the preset for the host; `CMakePresets.json` shows each only on its own OS. All use Ninja and RelWithDebInfo into `build/`:
  - Linux: `cmake --preset linux` (prefix `~/.local`). Packages: `scripts/ci-linux-deps.sh`.
  - macOS: `cmake --preset macos -DCMAKE_PREFIX_PATH=$(brew --prefix qt)`. Packages: `scripts/ci-macos-deps.sh` (Homebrew).
  - Windows: from a Visual Studio Developer prompt with Qt for MSVC on `CMAKE_PREFIX_PATH`, `cmake --preset windows`.
  - libvterm comes from pkg-config, else from its release tarball (`-DX3RO_DECK_BUNDLED_VTERM=ON` forces that).
- `cmake --build --preset <linux|macos|windows>`: build everything. The build must stay warning-free on GCC, Clang and MSVC; `x3ro_deck_set_warnings` in `CMakeLists.txt` picks the flags. Add `-DX3RO_DECK_WERROR=ON` to the configure step to turn warnings into errors (CI does).
- `cmake --install build`: install the binaries to `~/.local/bin`, plus the desktop file and hicolor icons. On macOS the app is a bundle (`x3ro-deck.app`, `data/macos/Info.plist.in`, `life.x3ro.deck`) with the hook, daemon and attach client in `Contents/MacOS`; it installs to `<prefix>/Applications`. `data/icons/x3ro-deck.icns` comes from `scripts/make-icns.py`. Without a native notification backend (`Notifier::isNative`), MainWindow shows a tray message instead. On Windows (MSVC) the build has the `.rc` icon and version info (`data/windows/x3ro-deck.rc.in`) and AppUserModelID `life.x3ro.deck`; it builds `x3ro-deck-sessiond` on ConPTY (the `Q_OS_WIN` branches in `sessiond/Daemon.cpp`: `spawn` with `CreatePseudoConsole`, a reader thread per session, `QWinEventNotifier` for exits, a `QLockFile` per pipe; `--detach` relaunches with `DETACHED_PROCESS | CREATE_BREAKAWAY_FROM_JOB`), `attach/AttachClientWin.cpp` (VT console mode, polled resize) and `ProcessInfoWin.cpp` (Toolhelp32); x3ro-deck-hook writes to the named pipe with `CreateFileW`/`WriteFile` (`AgentBus`'s `QLocalServer` listens on the same name); the Unix-only tests stay out, uses `PtyChannelNone.cpp`, and builds libvterm from its release tarball (`X3RO_DECK_BUNDLED_VTERM`, the fallback whenever pkg-config finds none). Docker Desktop's `npipe://` endpoint is supported, and a missing session daemon shows as the session panel's "The session daemon is required" notice. The desktop and icon rules apply only on `UNIX AND NOT APPLE`. The desktop file comes from `data/x3ro-deck.desktop.in` with an absolute `Exec`, because Plasma's session PATH lacks `~/.local/bin`.
- Linux: after changing the desktop file or icons, refresh the desktop's caches (`update-desktop-database ~/.local/share/applications`, plus the desktop's own menu cache rebuild).
- `-DX3RO_DECK_CORE_ONLY=ON`: skip the GUI app and its Qt Quick dependency, keeping the hook, `x3ro-deck-sessiond`, `x3ro-deck-attach` and every test. The Qt floor is 6.4 (Ubuntu 24.04 and Debian 12), and the full app builds there.
- `scripts/check-format.sh [--fix]`: check (or apply) `.clang-format` on every tracked C++ file.
- `scripts/check-spdx.sh [--fix]`: every tracked C++, Objective-C++, QML, CMake, shell and Python file starts with `SPDX-FileCopyrightText: 2026 x3ro` and `SPDX-License-Identifier: GPL-3.0-or-later` (after a shebang). New files need them; CI checks.
- `scripts/smoke-test.sh [binary] [out.png]`: headless screenshot in an isolated environment. It fails without a PNG or on any QML error.
- `ctest --test-dir build`: run the QtTest suites in `tests/`. They link `x3ro-deck-base`, the static library holding everything except the app executable's `main.cpp`, `MainWindow` and `TerminalHost`. `tst_qml` compiles every panel in `qml/`. `tst_sessionflow` drives AppController against a private tmux server, and again as `sessionflow-daemon` against a private `x3ro-deck-sessiond`. `tst_sessiond` covers the daemon's protocol (including the foreground job and process tree), `DaemonBackend`, the attach client in a PTY, `SessiondChannel` and `SessionScreen` redraws (checked against a `TerminalScreen` fed the raw output).

CI (`.github/workflows/ci.yml`) builds and tests on Linux (an `archlinux` container, and `ubuntu:24.04` with its distro Qt 6.4 and tmux 3.4), macOS (Homebrew Qt) and Windows (MSVC, Qt 6.8). Both build the full app with `-DX3RO_DECK_WERROR=ON`, run `ctest` and the smoke test, and upload the screenshot; the Arch job also checks formatting. `scripts/ci-linux-deps.sh` lists the packages. For UI changes, also inspect a screenshot yourself (see Workflow).

# Architecture

- `src/main.cpp`: app setup and the `SingleInstance` guard (a second launch raises the first window and exits). It relaunches the binary after `MainWindow::restart()`, releasing the guard first. Dev flags: `--tab <docker|agents>`, `--select N`, `--settings [checkouts|agents|docker|general|shortcuts]`, `--about`, `--edit-theme [id]`, `--screenshot <file> [delayMs]`. The screenshot captures an open dialog instead of the window.
- `--demo` (`src/DemoMode.{h,cpp}`): `AppController::enableDemo()` swaps in an in-memory config with invented checkouts, a `DemoBackend` whose terminals print canned transcripts (`DemoChannel`, also every shell tab through `TerminalHost::setChannelOverride`), and `seedDemo()` feeds git, PR, container and hook state through the normal handlers. It skips the single-instance guard, keeps QSettings in a temporary folder, disables Settings, notifications, the global hotkey and port probes, and runs no tmux, Docker, gh or git. CI uploads `demo-*.png` for the README.
- `src/AppController.{h,cpp}`: the only state owner. The context property `app` exposes it to QML through Q_PROPERTYs, `VariantListModel`s and Q_INVOKABLEs.
  - Each checkout runs one agent at a time in one tmux session. `AgentInfo::profile` names its `AgentProfile`; the pick persists in QSettings under `agents/<checkout>`.
  - A session that survives a restart keeps that pick. `ensureAgentSession` switches a freshly created session to the checkout's configured agent, and a renamed checkout takes over its old session, matched by path.
  - `reloadConfig` applies saved settings while running. A changed checkout list (names, paths or order) takes a restart.
  - `onHookEvent` maps hook payloads to the agent state machine: `offline | ready | working | permission | question | done`.
  - `publishAttention` builds the NEEDS YOU items. Priority order: permission, question, docker, done.
  - Each hook payload's `cwd` is matched to a checkout by the longest checkout path that contains it, with `Paths::isWithin`, so `/a/bc` never matches `/a/b`.
- `src/Paths.{h,cpp}`: path normalization (`~`, symlinks, separators, Windows drive letters) and comparison. It is case-insensitive on macOS and Windows. Checkout paths, hook cwds, tmux session paths and the Settings path fields all go through it.
- `src/Config.{h,cpp}`: `~/.config/x3ro-deck/config.json`, written with defaults on first run. User keys override defaults at the top level.
  - `configVersion` names the file's layout (missing = 0). `src/ConfigMigrations.cpp` holds one function per version step. `readJson` runs them on the user's keys before merging defaults, keeps the original as `config.json.v<N>.bak`, and writes the result. A file from a newer build is left untouched, and `configError` warns in the checkout rail, which also keeps Settings from saving over it.
  - To change the layout, append a migration. Its index is the version it upgrades from; add a fixture and a case to `tests/tst_configmigrations.cpp`.
  - `agents` is an ordered list of `AgentProfile`s. `kind` (`claude`, `codex` or `custom`) selects `kindDefaults`: command, resume args, process name, permission keys, prompt buttons and submit delay. Profile keys override them.
  - Fresh configs have two profiles, Claude and Codex; Claude's buttons are its built-in `/review` and a plain-text PR prompt. Migration v5 → v6 writes the older defaults (`/full-review`, `/create-pr`) into existing Claude profiles that relied on them.
  - `custom` runs any CLI. It sends no hooks, so only the pane poll tracks it, and its `process` defaults to the command's first word.
  - `env` makes a profile run its CLI against another backend. `AgentProfile::sessionEnv` expands `$VAR`/`${VAR}` against the app's own environment (unset → empty), and the session backend sets the result when it creates the session (`tmux new-session -e`). It is never typed, so it stays out of the pane and shell history.
  - A session's env is fixed at creation, and tmux records it in the session option `@x3ro-deck-env`. Start or Continue with a profile whose env differs kills the idle session and creates a fresh one; the attached terminal reattaches.
  - A checkout's `agent` key names the profile a fresh session starts; `defaultAgent` covers the rest.
- `src/AboutDialog.cpp`: credit, version (`PROJECT_VERSION`), source link (CMake cache `X3RO_DECK_SOURCE_URL`), `LICENSE` and the third-party notices in `data/licenses/` (resources of `x3ro-deck-base`). LICENSE's section 7(b) term requires modified versions to keep the credit. Opened from Settings → General and the tray. It and SettingsDialog derive from `DeckDialog`, which `data/style.qss` styles.
- `src/SettingsDialog.cpp`: the Settings dialog, a Widgets form over `config.json`. It edits the JSON itself, so keys without a field survive a save, and it leaves profile keys at their kind's defaults out of the file. `data/style.qss` styles it under `DeckDialog` and `QMessageBox` selectors.
- `src/MainWindow.cpp`: builds the widget layout with `QSplitter`s and one `QQuickWidget` per QML panel; all panels share one `QQmlEngine`.
  - Shortcuts come from `src/Shortcuts.{h,cpp}` (ids, labels, defaults); config.json's `shortcuts` holds rebound ones by id (`""` unbinds). `MainWindow::applyShortcuts` sets the actions and hands every binding to `TerminalHost::setAppShortcuts`, so terminals pass them to the window. Settings → Shortcuts edits them with `QKeySequenceEdit`, flags clashes and refuses to save while any remain. QML hints read `app.shortcutHints`. On macOS the defaults switch checkouts with ⌘+digit (⌥+digit types characters), and `MainWindow::buildMenuBar` adds a global menu bar from the same actions (About/Settings…/Quit with their menu roles, then Checkout and Window menus), so rebinding updates the menus. The global show/hide binding is only the portal's preferred trigger at first registration.
  - It also owns the terminals, shortcuts, the tray icon (`TrayIcon`) and notifications (`Notifier`). Notification actions come back tagged with the attention item id: `default` (the body click) reveals and opens it, `allow`/`deny` answer a permission.
  - Closing the window hides it to the tray, or minimizes it when the desktop has no tray. A tray click hides a window that was active just before the click (the click itself deactivates it).
  - Ctrl+Q and the tray's Quit go through `confirmQuit`, which offers to stop the agents by killing the tmux server.
  - Layout state persists in `~/.config/x3ro-deck/x3ro-deck.conf`.
- `src/TerminalHost.cpp`: hosts one built-in terminal (`TerminalView`). An agent terminal reads the backend's `attachChannel()` when it has one (the daemon); otherwise it runs the backend's attach command (or the imported shell for shell tabs) in a `PtyChannel`. `setProfile` applies imported settings to every open terminal at once.
- The built-in terminal lives in `x3ro-deck-base`, so `tst_terminal` covers it:
  - `TerminalScreen` wraps libvterm. It holds the cell grid and turns keys and pastes into bytes, honoring the program's modes. Ctrl combos use legacy control bytes, because libvterm would send CSI u.
    - Lines scrolling off the primary screen go to its scrollback, capped by the imported profile's history or else config `terminalScrollback` (default 10 000; unlimited means 100 000). "Line" numbers run through the history and then the screen. `droppedLines()` turns them into positions that survive lines dropping off the top.
    - libvterm has already shifted its line info when `sb_pushline` fires, so row 0's `continuation` flag says whether the pushed line soft-wraps. `text()` joins wrapped lines without a break, so a wrapped answer copies with its original line breaks.
  - `TerminalView` is a `QWidget` that paints the screen cell by cell and maps key events. Its grid follows the widget size and resizes the channel. It claims every key except the window shortcuts passed to `setReservedShortcuts`.
    - Scrolling: the wheel moves 3 lines a notch and Shift+PgUp/PgDn a page. New output never moves a scrolled-back view; typing or pasting snaps it to the bottom.
    - Selection: drag selects, double-click a word, triple-click a wrapped line. Release copies to the primary selection; Ctrl+Shift+C/V copy and paste; middle-click pastes the primary selection.
    - Mouse events (buttons, motion, wheel) go to the program only under `reportsMouse()` (it enabled mouse tracking and Shift is up); libvterm picks the tracking mode and encoding (X10, SGR 1006, …). A release follows its press. Under tmux (`mouse on`) every click therefore goes to tmux, and Shift selects locally. Without tracking on the alternate screen, the wheel sends arrow keys.
    - Cursor shape and blink start from the appearance and follow DECSCUSR afterwards; a reset returns to the appearance's. IME: the preedit is drawn at the cursor and the commit is typed. Glyphs from fallback fonts are centered in their cells, or shrunk when wider, so the grid stays aligned.
  - `TerminalChannel` is the byte stream behind a view. `PtyChannel` implements it with `forkpty`; `SessiondChannel` attaches to a sessiond session over its own socket (no `x3ro-deck-attach` process). Its `closed()` is always queued and follows the attach client's one-line note (session ended, lost the daemon, attach error); `MainWindow` then recreates the session and reattaches.
  - `TerminalAppearance` holds the font, colors, padding, line spacing and default cursor. `fallback()` uses the system monospace font and the theme's colors.
- Terminal settings import (also in `x3ro-deck-base`, covered by `tst_terminalsettings` with fixtures in `tests/fixtures/konsole/`):
  - The default shell (no imported profile) is the login shell on Linux and macOS; on Windows config `windowsShell` (`pwsh`, `powershell`, `cmd`, `bash` for Git Bash; empty = PowerShell 7, else Windows PowerShell) through `windowsShellArgv`, set from AppController with `setWindowsShell` and offered in Settings → General on Windows. Compose options are double-quoted on Windows.
  - `TerminalProfile` is what a source produces: a `TerminalAppearance`, the shell argv and an optional scrollback. `TerminalProfile::fallback()` is the login shell with `TerminalAppearance::fallback()`.
  - `TerminalSettingsSource` is one terminal emulator: `detect`, `profiles`, `defaultProfile`, `load`, `watchedPaths`, plus `desktopEntries`/`nativeDesktops` for picking the desktop's default. `readIni` parses KConfig-style INI (QSettings would split values at commas). Register new sources in `TerminalSettings::builtinSources()`.
  - `KonsoleSettings` reads `konsolerc`'s `DefaultProfile`, `konsole/*.profile` (following `Parent=` by path or file name) and `*.colorscheme`. Konsole compiles its own schemes in, so Breeze is embedded; unknown schemes fall back to it.
  - `src/GpuTerminalSettings.cpp`: kitty (`kitty.conf` with `include`/`globinclude`, so `current-theme.conf`), Ghostty (`config`/`config.ghostty`, `config-file` includes, `theme` from `ghostty/themes` in the config dir, the data dirs or next to the binary; `light:…,dark:…` takes the dark one) and Alacritty (`alacritty.toml` with `import`/`general.import`). Each has one profile, `default`, starts from that terminal's own default colors and font size, and watches every file it read. Fixtures in `tests/fixtures/gpu/`, covered by `tst_gputerminals`.
  - `src/DconfTerminalSettings.cpp`: GNOME Console, GNOME Terminal, MATE Terminal and Ptyxis, read through `dconf dump` (the `Dumper` in `DconfSource::Locations`; tests feed fixtures from `tests/fixtures/dconf/`). They re-import when `~/.config/dconf/user` changes. Unset colors and Ptyxis's compiled-in palettes fall back to the GNOME palette on libadwaita's light or dark view colors; `use-system-font` uses `org.gnome.desktop.interface monospace-font-name`. Covered by `tst_dconfterminals`.
  - `src/DesktopTerminalSettings.cpp`: xfce4-terminal (`xfconf-query -c xfce4-terminal -lv`, else xfconfd's `xfce4-terminal.xml`, else `terminalrc`) and COSMIC Terminal (one RON file per key under `cosmic/com.system76.CosmicTerm/v1/`, read by the small `CosmicTerminalSettings::parseRon`; a profile's `syntax_theme_dark/light` names a custom scheme from `color_schemes_*`, else the built-in COSMIC colors). Covered by `tst_desktopterminals`.
  - macOS: `src/ITerm2Settings.cpp` (portable XML-plist reader; binary plists go through `plutil -convert xml1`; DynamicProfiles JSON with `Dynamic Profile Parent Name`; covered by `tst_iterm2`) and `src/TerminalAppSettings.mm` (Apple only; NSKeyedUnarchiver for the archived NSColor/NSFont). On macOS they come first in `builtinSources`, so the first detected is the default.
  - Windows: `src/WindowsTerminalSettings.cpp` reads Windows Terminal and its Preview (JSONC `settings.json` in the package's LocalState or the unpackaged path; `profiles.defaults` merged into the profile; `colorScheme` from `schemes`, else the bundled Campbell) and Console Host (`HKCU\\Console` through a `Reader`; `ColorTableNN` is 0x00BBGGRR). They come first in `builtinSources` on Windows. Covered by `tst_winterminals`.
  - `TerminalSettings` resolves config `terminalSettings` (empty = the desktop default from kdeglobals, `xdg-terminals.list` or `XDG_CURRENT_DESKTOP`; `none`; or a source id) and `terminalProfile` (empty = the source's default), falls back to `TerminalProfile::fallback()`, and re-imports 150 ms after a watched file changes. AppController owns it (`terminalSettings()`) and re-selects in `reloadConfig`; MainWindow passes `changed()` to `TerminalHost::setProfile`. Settings → General has both pickers.
- `src/SessionBackend.h`: the interface that keeps agent sessions alive outside the app (create, ensure, rename, send keys, submit, foreground-process poll, attach command, kill). AppController and MainWindow use only this interface; nothing outside the backend may call tmux.
  - Sessions run the imported shell (`terminalSettings()->current().shell`). `SessionShell::resolve` looks it up on PATH and falls back to `$SHELL`, the passwd shell and `/bin/sh` when it is missing. A shell given alone runs as a login shell (argv0 `-name`), which is interactive on a PTY, so its rc files set PATH (nvm, `~/.local/bin`) before the agent command is typed in. An argv with arguments runs as given.
  - tmux sets `default-shell` in the same call as `new-session`, or passes an argv with arguments as the session command. The requested argv is recorded in `@x3ro-deck-shell`; the daemon gets the resolved argv as `command` plus `login` and lists the request as `shell`. Start or Continue recreates an idle session whose recorded shell differs, as with env. A session that recorded none (older builds) is kept. The config key `sessionBackend` picks the implementation at startup: `tmux` (the default when tmux is installed) or `daemon`. Settings → General → Sessions switches it, and `MainWindow::applySettings` asks what happens to sessions still in the old backend, then restarts: *Let running sessions finish* records `sessions/legacyBackend` in QSettings, and `AppController::createBackend` wraps both in `SwitchingBackend` (old sessions stay there until they exit; new ones start in the new backend; it emits `drained` and the record is cleared). *Restart agents now* kills the old sessions and records `sessions/resume`, whose checkouts `ensureAgentSession` starts with the continue line. `tst_backendswitch` covers the wrapper against a private tmux and sessiond.
- `src/TmuxManager.cpp`: the tmux backend. Agents run on socket `-L x3ro-deck`, with config `~/.config/x3ro-deck/tmux.conf`. `ensureSession` only creates sessions that are missing, so agents survive app restarts. `submit` types text and presses Enter in one tmux call, or after a delay.
- `src/DaemonBackend.cpp`: the `daemon` backend, a blocking request/reply client of `x3ro-deck-sessiond`.
  - Only `createSession` starts the daemon (`x3ro-deck-sessiond --detach`, found next to the app or on PATH; `$X3RO_DECK_SESSIOND_BIN` overrides). Everything else treats a missing daemon as no sessions.
  - `sendKeys` maps tmux key names to bytes (`keyBytes`). The session env is stored by the daemon and returned by `list`, the analogue of `@x3ro-deck-env`.
  - `attachCommand` runs `x3ro-deck-attach <session>`; the hint is `x3ro-deck attach <checkout>`. `attachChannel` gives the built-in terminal a `SessiondChannel`.
- `sessiond/`: `x3ro-deck-sessiond`, QtCore and QtNetwork only. It owns one `forkpty` per session running the shell the app resolved (or `$SHELL` as a login shell) in the checkout, and outlives the GUI (`--detach` forks, `setsid`s and returns once listening).
  - One daemon per socket, guarded by `flock` on `<socket>.lock`. It exits 60 s after its last session and client are gone, or when its socket file disappears.
  - It feeds each session's output into a `SessionScreen`. `attach` resizes the PTY and the screen to the client first, then sends `redraw()` as the first `Output` frame. Resizes from any client apply to both, and the last one wins. `screen` returns the screen as text.
  - `list` reports `foreground`, tmux's `pane_current_command`. With `processes: true` (the pane poll) it adds `foregroundGroup`, every process name in the foreground job with the leader first, so an agent behind a wrapper (`node codex.js`, a launcher script) still matches its profile. `processes` returns the session's process tree, for detected links.
- `src/ProcessInfo.{h,cpp}`: process inspection for the daemon (static lib `x3ro-deck-processinfo`, QtCore only). `commandName` follows tmux's `parse_window_name`; `foregroundNames` builds `foregroundGroup`. The platform layer (`foregroundGroup`, `process`, `tree`) is one file per OS: `ProcessInfoLinux.cpp` reads `/proc` (`task/*/children`, with a full scan as fallback), `ProcessInfoMac.cpp` uses libproc and `sysctl(KERN_PROCARGS2)` (as does `ListeningPorts` on macOS), and `ProcessInfoNone.cpp` reports nothing elsewhere. Windows (Toolhelp32) adds its own file.
- `src/SessionScreen.{h,cpp}`: the daemon's libvterm screen, QtCore only (static lib `x3ro-deck-sessionscreen`, since `TerminalScreen` needs QtGui). `redraw()` emits escape sequences that rebuild the cells, cursor, pen, title and alternate screen on a fresh terminal. It writes soft-wrapped rows without a cursor move, so the receiving terminal keeps the wrap. libvterm keeps the input modes private, so a small scanner tracks them from the same bytes: cursor keys, keypad, bracketed paste, mouse, focus, kitty keyboard flags and modifyOtherKeys, plus scroll region and origin mode. Scrollback and the primary screen hidden behind the alternate screen are not redrawn.
- `src/SessiondProtocol.h`: the daemon's wire format, documented there. Frames are a big-endian u32 length, a type byte and a payload: `Control` (JSON with `op`/`id`, replies with `re`, events with `event`), `Output` and `Input` (u32 session id plus bytes). Add ops or fields rather than bumping `kProtocolVersion`.
- `attach/AttachClient.cpp`: `x3ro-deck attach [--socket PATH] <checkout>`. It runs both as `x3ro-deck-attach` (QtCore only) and as the `attach` subcommand that `main.cpp` handles before `QApplication`. It uses raw mode, forwards `SIGWINCH`, and Ctrl+\ detaches. On exit it resets every mode a redraw can set.
- `src/SingleInstance.{h,cpp}`: one instance per user. A `QLockFile` at `<socket>.lock` (stale only when its owner's PID is gone) picks the primary, which listens on `x3ro-deck-instance.sock` in the runtime directory (`$X3RO_DECK_INSTANCE_SOCKET` overrides it). A later launch first tries to hand the primary its args and `XDG_ACTIVATION_TOKEN`/`DESKTOP_STARTUP_ID` as one JSON line, waits for `ok`, and exits. Trying the socket before the lock matters: after `cmake --install` the running owner's executable reads as deleted and QLockFile would call its lock stale.
- `src/TrayIcon.{h,cpp}`: `QSystemTrayIcon` with a Show/Hide and Quit menu. `QSystemTrayIcon` has no attention status, so NEEDS YOU swaps in the app icon with an amber badge (`withBadge`) and updates the tooltip.
- `src/Notifier.h`: desktop notifications with actions, one backend per OS picked by `Notifier::create`. `FreedesktopNotifier` (Linux) calls `org.freedesktop.Notifications` over QtDBus with `desktop-entry`/`x-kde-appname` hints, maps notification ids to caller tags, and forwards `ActionInvoked`, `ActivationToken` and `NotificationClosed`. `MacNotifier.mm` (macOS) uses UNUserNotificationCenter with one category per action set; without a bundle or authorization (unsigned dev builds) it logs why and reports `isNative() == false`, so MainWindow shows tray messages. `WinNotifier.cpp` (Windows) shows toasts through C++/WinRT with foreground-activated buttons under AUMID `life.x3ro.deck`, creating its Start menu shortcut when missing. `NotifierNone.cpp` shows nothing on other OSes. `tst_notifier` runs it against a fake server under `dbus-run-session`.
- `src/GlobalHotkey.h`: system-wide shortcuts, one backend per OS picked by `GlobalHotkey::create`. `PortalGlobalHotkey` (Linux) uses `org.freedesktop.portal.GlobalShortcuts`. It registers the app id with `org.freedesktop.host.portal.Registry` (ignored where missing), runs CreateSession → ListShortcuts, and calls BindShortcuts only for ids not bound yet, so the portal's dialog shows on first use only. Each portal request subscribes to `Request.Response` on its predictable path before calling. `Activated` carries an activation token. Without the portal it logs one line, and Meta+Alt+H still works inside the window. `MacGlobalHotkey.mm` registers Carbon hot keys (`RegisterEventHotKey`, no Accessibility permission; Qt's Ctrl is ⌘ and Meta is ⌃). `WinGlobalHotkey.cpp` uses `RegisterHotKey` with a native event filter for `WM_HOTKEY` (Meta is the Windows key). `tst_globalhotkey` runs it against a fake portal.
- `src/WindowActivation.{h,cpp}`: raises and focuses the window with a token that shows the user asked. `MainWindow::reveal(token)` uses it. The token comes from a second launch's `XDG_ACTIVATION_TOKEN`/`DESKTOP_STARTUP_ID`, a notification's `ActivationToken` or the hotkey portal's `activation_token`; Qt fills it in itself for tray clicks.
  - Wayland: the token goes into `XDG_ACTIVATION_TOKEN` just before `QWindow::requestActivate()`, which Qt's xdg-shell plugin passes to `xdg_activation_v1`.
  - X11 (xcb, optional at build time): it sends `_NET_ACTIVE_WINDOW` with source 2 (user-requested) and the startup id's `_TIME`, and sends `remove:` for the startup id so the launch feedback ends.
- `src/Dependencies.{h,cpp}`: finds the external programs (git, gh, the compose command's program, tmux with the tmux backend, and each profile's command) on the app's `PATH` and on the login shell's. The login `PATH` comes from running the imported shell once as `-l -i -c` with markers around the output; until it arrives nothing counts as missing. AppController exposes the results as `dependencies`, `composeMissing` and `current.agentMissing`, which `qml/Notice.qml` shows; Start does nothing while the agent's command is missing. Settings → General lists them.
- `src/Worktrees.{h,cpp}`: the first-run welcome screen's data. `discover` runs `git worktree list --porcelain` in the picked folder (or yields the folder alone), `candidates` names them uniquely, and `withCheckouts` writes them into the config JSON. With no checkouts configured (`AppController::firstRun`), MainWindow shows `qml/Welcome.qml` in place of the layout; Finish writes config.json and restarts, Cancel writes nothing.
- `src/HookInstaller.{h,cpp}`: Settings → Agents' Install/Uninstall buttons for `x3ro-deck-hook` in `~/.claude/settings.json` and `~/.codex/hooks.json`. Its own order-preserving JSON tree (QJsonObject would sort the user's keys) keeps every scalar as written and writes `JSON.stringify(x, null, 2)` layout, so a round trip changes whitespace at most. Ours = a command whose first word's basename is `x3ro-deck-hook`; install removes ours, then appends one group per event in `events()` (keep it in step with `onHookEvent`), and both actions copy the file to `.bak` first. A bare name that resolves to the same binary counts as installed.
- Quick commands: `src/CommandDetector.{h,cpp}` finds them in project files (`MakefileDetector`, `PackageJsonDetector` with the package manager from the lockfile, `JustfileDetector`, `TaskfileDetector`, `MiseDetector`, and toolchain ones in `src/ToolchainDetectors.cpp`; `src/DetectorUtil.h` holds the shared readers for TOML lines, JSONC and key order; all parse the files themselves rather than run the tool, since scans run on the GUI thread; a task's own doc line becomes `description`, shown under the button; register new ones in `CommandDetector::all()`, tested in `tst_quickcommands` with fixtures in `tests/fixtures/quick/`). `src/QuickCommands.{h,cpp}` (owned by AppController) scans each checkout, re-scans 150 ms after a `QFileSystemWatcher` change on the folder or a source file, merges config.json's manual `quickCommands` (source `Manual`; a checkout's own `checkouts[].quickCommands` go through `mergeQuickCommands`, replacing a global one with the same label in place, edited in Settings → Checkouts) and keeps pin/hide per checkout in QSettings (`quick/<checkout>/pinned|hidden`, keys `<source>:<label>`). Groups are free-form; `Theme.groupColor` keeps check/env/data's colours and hashes others onto `checkoutColors`.
- `src/AgentBus.cpp`: `QLocalServer` on the hook socket. It reads one JSON hook payload per connection.
- `common/x3ro-deck-socket.h`: the socket paths, shared with the hook and free of Qt. `sessiondSocketPath()` resolves the daemon's `x3ro-deck-sessiond.sock` the same way, with `$X3RO_DECK_SESSIOND_SOCKET` as its override. `$X3RO_DECK_SOCKET` overrides it. Otherwise it is `$XDG_RUNTIME_DIR/x3ro-deck.sock` on Linux and `$TMPDIR/x3ro-deck.sock` on macOS, or `/tmp/x3ro-deck-<uid>/x3ro-deck.sock` when those are unset or too long for `sun_path` (107 bytes on Linux, 103 on macOS).
- `hook/x3ro-deck-hook.cpp`: plain C++ with no Qt. `common/x3ro-deck-socket.h` also holds `cloexecPipe`, `unixStreamSocket` and `kSendNoSignal`, because macOS lacks `pipe2`, `SOCK_CLOEXEC` and `MSG_NOSIGNAL`. Claude Code runs it from `~/.claude/settings.json` and Codex from `~/.codex/hooks.json`; both send the same Claude-style JSON. It must always exit 0, print nothing and finish in milliseconds.
- `src/DockerClient.cpp`: Docker Engine API over a Unix socket (HTTP/1.0 over `QLocalSocket`). It subscribes to `/events` and filters containers by the `com.docker.compose.project` label.
- `src/DockerEndpoint.cpp`: picks that socket. The order is the `dockerHost` setting, `DOCKER_HOST`, the active docker context, then rootless Docker, Podman, Colima, OrbStack and `/var/run/docker.sock`. Only `unix://` works. Settings → Docker shows the result.
- Compose commands are per checkout (`checkouts[].compose.{up,down,restart}`, empty = `CheckoutConfig::defaultCompose`, which passes the checkout's `compose.files` (-f, in order), `profiles`, `envFile` and `project` (-p); Settings → Checkouts edits them, listing `ComposeFiles::detect`'s files). `AppController::checkoutForContainer` assigns containers: a checkout naming the project in `compose.project` first, then the checkout rooted exactly at the `working_dir` label, then the one holding the first `config_files` entry, and only for unlabeled containers the single checkout whose folder gives the same default project name (`defaultProjectName`). Subdirectory projects belong to none; `current.composeFound` drives the panel's "No compose file found". Migration v3 → v4 moved the old global `composeUp/Down/Restart` into every checkout. They and quick commands expand `{compose}` to the `composeBinary` setting (`docker compose`, `docker-compose` or `podman compose`).
- Browser links (`AppController::links`): the configured `links`, then every published port of the current checkout's running containers that `PortProbe` found to answer HTTP (one `HEAD /` with a 500 ms timeout per port, re-probed once a port goes away and comes back), named after the service, then ports the user's processes whose working directory is inside the checkout listen on (`src/ListeningPorts.cpp` reads `/proc/net/tcp{,6}` and `/proc/<pid>/fd`; `AppController::scanListeningPorts` every 3 s), named after the program, through the same probe. Migration v4 → v5 dropped `portOffset`.
- `src/GitWatcher.cpp`: watches `HEAD` and `logs/HEAD` with `QFileSystemWatcher`.
- `src/PrWatcher.cpp`: polls `gh pr view <branch> --json …` per checkout.
- Themes: `src/AppTheme.{h,cpp}` loads `data/themes/cyberdecker.json` (the built-in default) and overlays the config's `theme`, a file in `~/.config/x3ro-deck/themes/<id>.json` or another built-in, so a theme only lists what it changes. MainWindow sets it as the QML context property `appTheme`. Themes switch live: `AppTheme::select` emits `changed` (MainWindow then refills the style sheet and QQuickWidget clear colors; Theme.qml's bindings follow). `theme: "system"` shows `themeLight`/`themeDark` (default `cyberdecker-light`/`cyberdecker`) by `QStyleHints::colorScheme` (Qt ≥ 6.5; 6.4 stays dark). Settings → General's picker lists `AppTheme::available()` (built-ins, then valid user files) and previews on change; Cancel reselects the saved theme. Its "Edit theme…" opens `src/ThemeEditor.cpp` (`MainWindow::editTheme`): every color, the checkout colors and fonts, previewed through `AppTheme::preview`; a built-in is edited as "<name> (copy)" saved under a fresh id (`AppTheme::idFor`); Save/Import write `themes/<id>.json` and `saved` refreshes the picker; Cancel previews the picker's choice again. `data/style.qss` and `data/ui/*.svg` are templates: `fill` replaces `${token}`, `${token/alpha}`, `${font.sans}` and `${icon:name}`, and the recolored icons go to `~/.cache/x3ro-deck/theme/<hash>/`. These files are resources of `x3ro-deck-base` (`qt_add_resources` in `CMakeLists.txt`), not `resources.qrc`. A new color needs a token in the JSON, in `Theme.qml` (with its fallback) and possibly in the templates; `tst_theme` checks that every token resolves and that `qml/` has no hex colors outside `Theme.qml`.
- `qml/`: `Theme.qml` holds every color and font token, reading `appTheme` with Cyberdecker's values as fallbacks. Use its tokens and helpers (`agentColor`, `healthColor`, `elapsed`, `alpha`) and do not hardcode colors.
- New QML files and data files must be added to `resources.qrc` (theme files: see Themes). New C++ sources must be added to `CMakeLists.txt`, to `x3ro-deck-base` unless they need Qt Quick, and new tests to `tests/CMakeLists.txt`.

# Code style

- Match the existing Qt idiom: `QStringLiteral`/`QLatin1String`, `Q_EMIT`/`Q_SIGNALS`, `std::as_const` in range-for loops, and anonymous namespaces for file-local helpers.
- Keep comments sparse. Explain why, not what.
- Name QML model roles carefully: `id` is reserved in QML delegates. The attention model therefore exposes the id as `itemId`.
- QML `font.pixelSize` takes an int. A fractional value fails with "Invalid property assignment" and blanks the whole panel.

# Workflow

- QML is compiled into the binary through `resources.qrc`, so rebuild before every screenshot.
- Run a headless screenshot after every UI change and inspect the PNG. Add `--settings <page>` to capture the Settings dialog, or `--demo` for made-up data that touches nothing (no config, tmux, Docker or gh).
  ```
  QT_QPA_PLATFORM=offscreen QT_QUICK_BACKEND=software QT_FORCE_STDERR_LOGGING=1 \
    ./build/x3ro-deck --demo --tab agents --select 0 --screenshot out.png 9000
  ```
  On Linux, wrap it in `dbus-run-session --` so the tray and notifications stay off the desktop's bus. On macOS the binary is `build/x3ro-deck.app/Contents/MacOS/x3ro-deck`, on Windows `build\x3ro-deck.exe`.
- Simulate agents by piping hook JSON into `./build/x3ro-deck-hook` with the test instance's `X3RO_DECK_SOCKET`.
- IMPORTANT: the user usually has the app running. A test instance against real data must not reach it:
  - On every OS, point the three sockets at private paths (named pipes on Windows: any name): `X3RO_DECK_SOCKET` (hooks), `X3RO_DECK_INSTANCE_SOCKET` (otherwise the test only hands its args to the live instance and exits) and `X3RO_DECK_SESSIOND_SOCKET` (a private session daemon).
  - Give it a private config: `XDG_CONFIG_HOME` on Linux, `HOME` on macOS (Qt reads `~/Library/Preferences`), `LOCALAPPDATA` on Windows, holding `{"autostartAgents": false}` in `x3ro-deck/config.json`. Set `GH_CONFIG_DIR` to the real gh config so `gh` stays authenticated.
  - With the tmux backend (Linux, macOS), set `TMUX_TMPDIR` to a private directory. The test then runs its own `-L x3ro-deck` server, which is safe to kill. Without it, the test attaches to the live `-L x3ro-deck` server: NEVER run `tmux kill-server` or `kill-session` against that server, or choose "Stop agents and quit" in a test attached to it, because its sessions hold the user's live agents.
  - Linux shortcut: one private 0700 directory with a short path as `XDG_RUNTIME_DIR` (and `TMUX_TMPDIR`) moves all three sockets and the tmux server at once.
- QML errors go to journald unless `QT_FORCE_STDERR_LOGGING=1` is set.
- `cmake --install` succeeds while the app runs. The user restarts the app (Ctrl+Q, then relaunch) to pick up the new binary, and agents keep running in tmux.
- Edit `~/.claude/settings.json` and `~/.codex/hooks.json` only by merging. Other hooks (a notifier, a linter) live alongside `x3ro-deck-hook`.

# Quirks

- Permission buttons send keys to the agent's tmux pane. Claude Code uses `1` for Allow, `2` for Always and `Escape` for Deny; Codex uses `y`, `a` and `Escape`. A profile's `permissionKeys` overrides them.
- Claude Code offers Always only when the payload has `permission_suggestions`; Codex offers it on every prompt.
- `AskUserQuestion`, `request_user_input` and `ExitPlanMode` become questions, not permissions, because their prompts are not allow/deny choices.
- Codex differs from Claude Code in four ways:
  - It sends no `Notification` events.
  - It sends `Interrupt` when a turn is cancelled.
  - It reports file edits as `apply_patch`, whose patch text names the files.
  - It runs a user hook only after the user trusts it with `/hooks`. The session panel warns when a freshly started agent sends no hook events for 15 s.
- Codex treats Enter within 120 ms of fast input as a newline, so its profiles wait `submitDelayMs` (300) before pressing Enter.
- A profile that points Claude Code at another server must set `ANTHROPIC_AUTH_TOKEN`; otherwise Claude Code sends the claude.ai login to that server.
- The pane poll (`onPaneCommands`) changes agent state only on transitions of an agent process inside our own session. All other state comes from hooks. `foregroundProcesses` gives each session a list of names: tmux sends `pane_current_command` alone, and the daemon adds the rest of the foreground job. A profile runs when any name starts with its `process`. When the pane runs another profile's `process`, the checkout switches to that profile; the current profile is checked first, then the names in order.
- libvterm's `CSI ?1049l` without an earlier `?1049h` restores an all-zero pen, which paints text black on black. `SessionScreen::redraw` therefore leaves the alternate screen with `?1047l`.
- tmux before 3.5 prints tabs in `-F` output as `_`, so `TmuxManager` separates fields with `:`. Session names never contain `:`.
- Exited containers with exit code 0 count as `completed`. They are excluded from up/total counts and never raise NEEDS YOU items.
- `PrWatcher` first checks `gh auth status` (missing or logged out → `PrInfo::problem`, shown by the session panel, no polling), then per branch reads origin's URL (non-GitHub → "No GitHub remote") and the default branch (`refs/remotes/origin/HEAD`, else `gh repo view`, else `main`/`master`/`develop`), and skips the default branch. A closed, unmerged PR turns "View PR" back into the profile's `prPrompt`.
- Under `dbus-run-session`, the app's portal and notification calls may start or time out against services on the private bus, and it logs one line for each. These are expected in headless tests.
- The icon source is `data/icons/x3ro-deck.svg`. After editing it, regenerate the PNGs with `rsvg-convert -w N -h N` and the ICO with `magick x3ro-deck-{16,24,32,48,64,128,256}.png x3ro-deck.ico`.
